# A/C 对照实验协议（v1，跑之前冻结）

回答的问题：在**相同的基础流程**下，动态取数究竟解决了哪些固定工作流解决不了的问题，代价多大。

- **A 臂**：固定工作流 = 基础取数 + 单次判定节点。
- **C 臂**：级联 = 固定工作流先行，**仅歧义档**进入受控 Agent 子图。

## 1 评测对象冻结（不按结果重划子集）

- 输入：`inputs_50.json`（执行 commit 见 `benchmark50_finalize.json`）；gold 与
  第一层 Gate 的 `agent_needed` 标签沿用，**不改案例、不重建输入**。
- 除整体与 Agent-needed 子集的分诊正确性，另单独记录三项路由统计：
  1. Agent-needed 案例中 **C 实际进入子图的比例**；
  2. 非 Agent-needed 案例中 **C 进入子图的比例**；
  3. Agent-needed 但**被路由到固定路径**的案例清单及原因码。
- 口径纪律：**gold 标记为 Agent-needed ≠ 路由一定会识别它**；实际是否进入子图是系统表现的一部分，
  不得为了让子集好看而把这些案例强行送入 Agent。

## 2 预算定义（不笼统说"调用量相同"）

- 两臂共享：**相同工具集、相同基础取数流程、相同模型与生成参数**（temperature=0）。
- C 的动态预算：**单次子图最多 4 次工具调用**（沿用 `agent_subgraph.run(budget=4)`）。
- 表述纪律：可以说"相同工具集、相同基础取数与预先设定的预算约束"，
  **不得**声称"两臂实际使用了相同数量的工具调用"——额外调用量正是被测量的结果。
- 本轮**不设**每案例总调用上限；若要设，必须在代码里显式执行并记进本文件。

## 3 失败保留在样本中（不剔除、不丢样本）

模型超时、工具报错、Agent 预算耗尽、输出 schema 无效等，**全部保留在评测样本中**，
按协议计为"安全转人工"，**既不剔除案例，也不只统计成功样本**。

这里要区分两个指标，**不能合并成一个笼统的失败指标**：

- **安全转人工率**：记录**最终处理结果**（多少案例最终交给人工）；
- **失败原因分布**：记录**系统为什么转人工**（`TOOL_FAILED` / `BUDGET_EXHAUSTED` /
  `NO_NEW_EVIDENCE` / `REPEATED_CALL` / schema 无效等），逐原因分别保存计数。

每案例两臂各留一条运行记录，至少含：`case_id`、`run_id`、`route`、工具调用轨迹、
原始模型输出、最终判定、错误或停止原因码、token 用量、端到端耗时。
**两臂都从干净的案例级状态启动**，避免前一案例影响后一案例。

## 4 质量 rubric（先定口径，再看结果）

- 分诊正确性：与 gold 一致；整体与 Agent-needed 子集**分开报**。
- 证据包完整性：不只看"引用了几条 fact"，还要检查**是否覆盖判定所需关键事实、
  引用是否有效（属于本次执行）、结论是否确由证据支撑**。
- 草稿质量：A/C 输出**混排且隐藏臂标识**，按同一 rubric 评四维——
  **正确性 / 证据支撑 / 可执行性 / 是否出现未经授权的承诺**。
- 原始模型输出、运行日志、盲评结果**分别保存**。
- P95 允许报告，但在 50 条样本下**只作描述性指标**，不当作稳定性能保证。

## 5 决策规则（跑之前写下"什么算值得保留"）

优先看 **Agent-needed 子集的改善**，同时检查：整体是否回退、证据质量是否下降、
安全转人工是否异常升高、成本与延迟是否可接受。

**本轮明确标为探索性对照**：数值阈值未预先设定，因此**不把 50 条的小样本结果
包装成统计显著性结论**。最终保留 Agent、降级为工作流、或判定"当前实验无法得出结论"，
都是合法产出。**不预设 Agent 必须赢。**
